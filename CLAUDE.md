# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Revision of the paper "Revisiting Elasticities of alcoholic and non-alcoholic Beverages in Colombia" (Maldonado & García), responding to Food Policy reviewer comments. It estimates own-price, cross-price and expenditure elasticities for sweetened beverages, beer, water, dairy drinks and hot drinks from Colombia's ENPH 2016–2017 household budget survey. **R does all data processing, validation and reporting; Stata only runs WELCOM's `duvm` and its inference.** `README.md` describes the pipeline for users. The pipeline is new, **not** a replication of the earlier estimates (the replication-first plan in `dev/README.md` was superseded on 2026-11-17).

## Commands

- Full run (PowerShell, not Git Bash, which rewrites Stata's `/e` flag): `powershell -ExecutionPolicy Bypass -File run_pipeline.ps1 -Stage all -RunId <id>`. Stages, also usable as a comma-separated list: `construct`, `check`, `point`, `bootstrap`, `inference`, `report`, `manuscript`. `-Workers <n>` overrides `parallel_workers` (12).
- R stages: `Rscript code/R/00_run.R <load|households|consumption|prices|validate|construct|report|manuscript> --run-id=<id>` (`construct` = `load` … `validate`). Logs and JSON manifests go to `output/logs/<run_id>/`.
- Stata stages: `code/stata/00_master.do "<root>" <run_id> <check|point|boot|inference|all> [worker nworkers]`. Batch Stata returns no exit code; each stage writes `output/logs/<run_id>/stata_<stage>.ok`, which the wrapper checks.
- No unit tests. Checks are: `validate` (data checks), Stata `check` (matrix orientation on simulated data, `90_orientation_check.do`), and the table-completeness check at the end of `report` (`output/tables/<run_id>/table_completeness.csv`).
- The manuscript render refuses an incomplete or mismatched bundle; `ALLOW_INCOMPLETE=1` overrides the completeness check. It never installs LaTeX packages.
- `python code/R/tools/write_alternatives_register.py` regenerates `metadata/alternatives_register.csv` and `docs/estimation_alternatives.md` from one list; edit the script, not the outputs. `code/R/tools/write_renv_lock.R` writes `renv.lock` without installing renv.
- Legacy rerun (unchanged legacy code, ~14 min): `powershell -ExecutionPolicy Bypass -File code\replication\run_legacy.ps1`.

## Configuration and data flow

- `config/config.yml` is the single source of paths, parameters, seeds and replication counts. `config/models.csv` is the model registry (32 models: M1–M6 specifications, T1–T3 income terciles, S1–S7 sensitivity, each for `home` and `combined` markets). `config/local.yml` (git-ignored, from `local.example.yml`) holds executables, `pandoc_dir`, `stata_scratch_dir`. `config/stata_params.do` is generated by R; do not edit it.
- Rules live in `metadata/*.csv` (COICOP/category map, text rules, Capítulo C groups, frequency factors, unit conversions, price clusters, table registry). Change rules there, not in code.
- R writes `data/interim/01_import` … `04_prices` and the analysis-ready files in `data/processed/estimation/`; Stata reads those, writes `output/estimates/<run_id>/`; R `report` builds tables, figures and the manuscript bundle in `data/processed/manuscript/<run_id>/`; `manuscript` renders to `output/manuscript/<run_id>/` (LaTeX scratch in `manuscript/_render/`).
- Everything is keyed by run id: `output/{estimates,diagnostics,tables,figures,manuscript,logs}/<run_id>/`. Do not mix runs.
- The bootstrap is slow (a `duvm` call takes 20–30 s, ~75 main replications an hour on 12 workers) and resumable: one file per replication in `data/processed/bootstrap/<run_id>/`. Changing anything that alters `data/processed/estimation/*.dta` invalidates existing replications: delete them and rerun.

## Layout

- `code/R/lib/` side-effect-free functions; `code/R/01_load` … `07_manuscript` stages; `code/R/tools/` maintenance scripts.
- `code/stata/`: `00_master.do`, `01_setup.do`, `10_programs.do` (WELCOM wrappers and input contract), `20_point_estimates.do`, `30_bootstrap_worker.do`, `40_inference.do`, `90_orientation_check.do`. `code/stata/ado/` pins WELCOM 3.60 and estout: never modify or update them.
- `code/legacy/` and `code/old/` are the frozen legacy code; `code/replication/` reruns it unchanged (outputs in `output/replication/`). Do not edit them. `output/old/` holds legacy outputs.
- `data-raw/` holds the ENPH `.sav` modules and questionnaires (immutable). `data/` is git-ignored household-level data.
- `docs/`: `methods.md`, `welcom_method.md`, `corrections_log.md`, `legacy_to_new_map.md`, `estimation_alternatives.md`, `blockers.md`, `reproducibility_audit.md` (legacy audit), `Paper_20_1012_ElasticiBeverages.pdf` (earlier manuscript), `DSO-ENPH-MET-001-V2.pdf` (DANE methodology). `docs/FP Review.pdf` is confidential.
- `manuscript/manuscript.Rmd` renders from the bundle of one run; every estimated number in the text is inline code. Do not hard-code results.
- `reports/` slides support files; `dev/` historical plan and the prompts that produced the pipeline.

## Conventions

- WELCOM `duvm` is the only estimator for the tables. Calling-side and data-construction errors are corrected (log them in `docs/corrections_log.md`); estimator-level concerns go to the alternatives register, not into the code.
- Use the label **SB (sweetened beverages)**, not SSB: ENPH cannot separate sugar-sweetened from non-sugar-sweetened drinks.
- Elasticity matrices: **rows = category whose quantity responds; columns = category whose price changes.** Estimates are uncompensated and unconditional (shares and regressor use total household expenditure). Say "expenditure elasticity", not "income elasticity".
- Keep observed zeros distinct from missing values. Unit values exist only for buyers with a recorded quantity and are never imputed. Spirits and wine have no quantities in ENPH and are not estimable.
- Do not install or update Stata, R or LaTeX packages silently. Record versions, seeds and logs for every run.
- Never commit microdata, household-level files, free-text survey responses or the confidential review documents. `.gitignore` covers `data/`, `data-raw/`, logs, `manuscript/_render/` and local configuration. Commit `7a51561` already contains some of these (see `docs/blockers.md`); do not rewrite history without the authors.
- Key ENPH identifiers: `DIRECTORIO` (household, `hhid` in the pipeline), `VIVIENDA` (dwelling: municipality|sector|section|block|dwelling; municipality + sector is the survey segment), `FEX_C` (expansion factor). The primary price cluster is the local market: municipality × area (urban/rest) × collection quarter; segments are sensitivity S5.
- Branch naming: `revision/<topic>`.
- In Bash heredocs on this machine, backslashes are halved; write regexes with character classes (`[.]`) or use script files.
